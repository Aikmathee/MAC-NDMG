# แผนปรับ Network Drives ให้เป็น Liquid Glass บน Mac

วันที่: 21 ตุลาคม 2026

สถานะ: **อนุมัติให้ดำเนินการแล้ว — เริ่มส่งมอบใน v2.2.0**

ผลการทำงานและข้อจำกัด: [LIQUID_GLASS_IMPLEMENTATION.md](LIQUID_GLASS_IMPLEMENTATION.md)

ฐานที่ตรวจ: โค้ด v2.1.1 และภาพหน้า Groups / Connected ที่ตรวจในแอพจริง

## 1. เป้าหมาย

ให้แอพดูและรู้สึกเป็นแอพ Mac รุ่นใหม่: แถบควบคุมมีมิติและตอบสนองต่อการใช้งาน เนื้อหาดูสงบ อ่านง่าย และเปิดมาก็รู้ว่ามีอะไรเชื่อมอยู่

ผลที่ต้องการ:

- ชั้นนำทางและชุดคำสั่งมีความเป็น Liquid Glass ชัดขึ้น
- Sidebar, toolbar, การเลือกไดรฟ์ และหน้าต่างเข้าสู่ระบบใช้ภาษาการออกแบบเดียวกัน
- หน้า Overview ช่วยให้กลับไปทำงานต่อได้ทันที
- Dark / Light / System ดูดีครบ และเคารพการตั้งค่าการช่วยการเข้าถึง
- รักษา Command-click, Shift-click, คีย์บอร์ด, คลิกขวา และการทำงานกับกลุ่ม
- ยังเปิดใช้งานบน macOS 13 ขึ้นไปได้ โดยแยกประสบการณ์ macOS 26 กับวัสดุทดแทนบนระบบเก่าอย่างชัดเจน

## 2. หลักจาก Apple ที่ใช้กำหนดทิศทาง

Liquid Glass เป็นชั้นสำหรับการนำทางและการควบคุมที่อยู่เหนือเนื้อหา ส่วนพื้นหลังและเนื้อหาใช้วัสดุมาตรฐานเพื่อรักษาลำดับสายตา การวางกระจกจึงต้องสัมพันธ์กับหน้าที่ของแต่ละส่วน [1][3]

เริ่มจากองค์ประกอบระบบและ SDK รุ่นใหม่ แล้วตรวจพื้นหลังที่วาดเองซึ่งอาจบังเอฟเฟกต์ของระบบ รวมถึงพฤติกรรมขณะเลื่อน ย่อขยาย และเปิด sheet [2]

ส่วนที่จำเป็นต้องทำเองจึงค่อยใช้ `glassEffect`, ปฏิสัมพันธ์ และ `GlassEffectContainer` โดยจำกัดจำนวนเอฟเฟกต์และใช้การเปลี่ยนรูปเฉพาะเมื่อช่วยสื่อความสัมพันธ์ของคำสั่ง [4]

รายละเอียดด้านล่างเป็นข้อเสนอสำหรับแอพนี้ ค่าระยะ สี และเวลาของ animation เป็นจุดเริ่มต้นสำหรับทดลอง ไม่ใช่ข้อกำหนดของ Apple

## 3. สิ่งที่พบจากแอพปัจจุบัน

| จุด | สภาพปัจจุบัน | สิ่งที่ควรปรับ |
| --- | --- | --- |
| วัสดุ | `GlassSurface` สร้าง `NSGlassEffectView` ผ่าน runtime บน macOS 26 และใช้ `NSVisualEffectView` บนระบบเก่า | ใช้ API ที่ตรวจชนิดได้เมื่อ build ด้วย SDK 26 และแยกบทบาทของวัสดุ |
| โครงหน้าต่าง | `HStack` กับ sidebar กว้างคงที่ 246 จุด | ทดลอง split view และ toolbar ระบบที่ย่อขยายได้ |
| ปุ่ม | `PillStyle` วาดพื้นผิว ขอบ gradient และสถานะกดเอง | ให้ปุ่มระบบดูแลรูปทรงและปฏิสัมพันธ์เป็นหลัก |
| การ์ด | `GlassCard` ใช้กับแถวข้อมูลและส่วนตกแต่งหลายชนิด | แยกการ์ดข้อมูลออกจากกระจกของชุดควบคุม |
| Groups | v2.1.1 แก้หัวข้อและกรอบเลือกเหลี่ยมแล้ว | จัดความสัมพันธ์ระหว่างกลุ่ม ไดรฟ์ และคำสั่งที่ใช้ร่วมกัน |
| การเลือก | `CardSelection` วาดสีและขอบโค้ง โดย `CardSelectionAnchor` ปิด highlight ของ AppKit | รักษาการเลือกแบบ native และทดสอบ focus ให้ชัดเจนทุก appearance |
| การเคลื่อนไหว | ปุ่มมี opacity / scale แบบกำหนดเอง | เพิ่ม transition ที่สัมพันธ์กับบริบทและมี Reduce Motion fallback |
| ฟอร์ม | มี sheet แล้ว แต่ระยะและองค์ประกอบวางเอง | ตรวจระบบ Form, ระยะขอบ, keyboard focus และขนาด sheet |

ข้อสังเกตเรื่องความแบนของภาพเป็นการประเมินจากโค้ดและหน้าจอ ไม่ใช่ผลวัดประสิทธิภาพ ยังไม่ได้ profile การเรนเดอร์หรือเปรียบเทียบ SDK 26

## 4. ภาพรวมหน้าตาที่เสนอ

### 4.1 หน้าต่างและ sidebar

- ทดลอง `NavigationSplitView` ให้ sidebar ย่อขยายและซ่อนได้ตามขนาดหน้าต่าง
- ใช้ title bar / toolbar ของ macOS ให้ปุ่มหน้าต่าง ชื่อหน้า และคำสั่งอยู่ในโครงเดียวกัน
- จัด sidebar เป็น Overview, Connected, Groups แล้วตามด้วย Servers
- ให้ Search เป็นช่องค้นหามาตรฐานในตำแหน่งที่คงที่
- ให้พื้นผิว sidebar สัมพันธ์กับเนื้อหาด้านหลัง โดยข้อมูลยังอ่านได้ทั้งหน้าต่าง active และ inactive
- ลดเส้นแบ่งแข็งและพื้นสีที่ซ้อนทับวัสดุระบบ

### 4.2 Toolbar และคำสั่งหลัก

- จัดคำสั่งตามหน้าที่: Refresh / Add server / New group และคำสั่งของรายการที่เลือก
- ใช้ปุ่ม native เป็นจุดเริ่มต้น บน macOS 26 ทดลอง `.glass` และ `.glassProminent` เฉพาะตำแหน่งที่เหมาะสม
- กลุ่มคำสั่งสำคัญมีพื้นผิวร่วมกัน แทนการให้ทุกปุ่มเด่นเท่ากัน
- Primary action ใช้ accent color ของระบบ ส่วน Eject ใช้ลำดับรองที่หาเจอได้ง่าย
- คำสั่งที่ใช้ไม่ได้ต้องมี disabled state ชัดเจน และไม่เคลื่อนตำแหน่งโดยไม่มีเหตุผล

### 4.3 Overview

ลำดับเนื้อหาที่เสนอ:

1. **Connected** — จำนวนและไดรฟ์ที่ใช้งานอยู่ พร้อม View all
2. **Groups** — กลุ่มที่บันทึกไว้และ Connect group
3. **Servers** — เครื่องที่พบและ Add server

- ย่อข้อความเกริ่นและไอคอนตกแต่งเพื่อให้เห็นสถานะงานก่อน
- ถ้ายังไม่เคยตั้งค่า ให้แสดงจุดเริ่มต้นเดียวที่ชัดเจน เช่น Add server
- แยกสถานะกำลังค้นหาออกจากสถานะยังไม่มีเซิร์ฟเวอร์
- ไม่เพิ่มภาพพื้นหลังหรือเอฟเฟกต์สีขนาดใหญ่เพื่อให้ดูเป็นกระจก

### 4.4 Connected และรายการไดรฟ์

- ใช้แถวข้อมูลที่อ่านชื่อไดรฟ์ เครื่องปลายทาง และสถานะได้ในลำดับเดียวกัน
- คงสีเลือกและขอบโค้งที่แก้แล้วใน v2.1.1
- ปรับความหนาแน่นให้เห็นรายการมากขึ้น โดยปุ่ม Open / Eject ยังคลิกได้สะดวก
- แยก selected, hovered, keyboard-focused, connected, waiting และ failed ออกจากกัน
- เมื่อเลือกหลายรายการ แสดงชุดคำสั่งรวมที่ขอบล่างด้วยวัสดุกระจกหนึ่งชุด และเว้นพื้นที่ไม่ให้บังแถวสุดท้าย
- ทดลอง scroll edge effect กับขอบเนื้อหาที่อยู่ใต้ toolbar โดยไม่ทำให้ชื่อไดรฟ์อ่านยาก

### 4.5 Groups

- หัวข้อ Groups และ Saved drives เป็นข้อความเรียบ ไม่มีแถบทึบเหลี่ยม
- การ์ดกลุ่มแสดงชื่อ จำนวนที่เชื่อมอยู่ และตัวอย่างสมาชิกพอให้แยกกลุ่มได้
- Connect group เป็นคำสั่งหลัก; Eject group และ Edit อยู่ในตำแหน่งที่คาดเดาได้
- Empty state เป็นการ์ดโค้งมนที่มี New group ชัดเจน
- เมื่อเลือกกลุ่มร่วมกับไดรฟ์ ให้แสดงจำนวนปลายทางหลังตัดรายการซ้ำ
- การเปลี่ยนสถานะกลุ่มต้องไม่ทำให้การ์ดสั่นหรือความสูงเปลี่ยนตลอดเวลาที่ refresh

### 4.6 Sheets และ popovers

ครอบคลุม Add server, Sign in, New/Edit group และ Activity:

- ใช้ sheet และ form ของระบบให้มากขึ้น ตรวจว่าพื้นหลังที่เพิ่มเองไม่บังวัสดุระบบ
- กำหนดระยะขอบให้รับกับมุมโค้งของหน้าต่าง
- Cancel / Continue / Save อยู่ตำแหน่งเดียวกัน และรองรับ Escape / Return ตามบริบท
- ข้อผิดพลาดแสดงใกล้ช่องที่เกี่ยวข้อง ใช้ภาษาสั้นและไม่ทำให้ layout กระโดด
- เก็บ Remember this server และพฤติกรรม Keychain เดิมทั้งหมด
- ใช้ popover สำหรับตัวเลือกสั้น ๆ ที่สัมพันธ์กับปุ่มต้นทางเท่านั้น

## 5. ระบบวัสดุ รูปทรง และสี

| บทบาท | แนวทางที่เสนอ |
| --- | --- |
| พื้นเนื้อหา | สีพื้นตาม appearance ของระบบ อ่านข้อมูลได้ชัด |
| การ์ดข้อมูล | วัสดุมาตรฐานหรือพื้นเรียบที่มีความต่างระดับเล็กน้อย |
| Sidebar / navigation | วัสดุและพฤติกรรมระบบเป็นหลัก |
| Toolbar / คำสั่งรวม | Liquid Glass ที่แยกจากเนื้อหาอย่างชัดเจน |
| Primary action | glass prominent หรือปุ่ม native ที่เด่นด้วย accent |
| Selection | tint อ่อนและขอบโค้งในรูปทรงเดียวกับแถว |
| Error / warning | สี semantic พร้อมข้อความหรือสัญลักษณ์ ไม่อาศัยสีอย่างเดียว |

ข้อเสนอเริ่มต้นสำหรับทดลอง:

- รวม corner radius เป็นกลุ่ม เช่น control, row, panel โดยเริ่มประมาณ 12 / 18 / 24 จุด แล้วปรับตามรูปทรงและระยะซ้อนจริง
- รวม spacing เป็นชุด 8 / 12 / 16 / 24 / 32 จุด
- ใช้ font แบบ semantic ของระบบเป็นหลัก ให้ชื่อและสถานะสำคัญอ่านได้ชัดก่อนตกแต่ง
- ลดขอบสีขาวและเงาที่วาดซ้ำบนวัสดุซึ่งระบบดูแลให้แล้ว
- ให้มุมของ highlight, hover, focus และการ์ดใช้รูปทรงเดียวกัน

## 6. ปฏิสัมพันธ์และการเคลื่อนไหว

- ทดลอง hover / press ของปุ่ม glass ระบบก่อนเพิ่ม animation เอง
- ชุดคำสั่งรวมปรากฏเมื่อเริ่มเลือก และหายเมื่อยกเลิกการเลือกโดยไม่มีการกระโดดของเนื้อหา
- ทดลอง `GlassEffectContainer` เฉพาะชุดคำสั่งที่อยู่ใกล้กันและมีความสัมพันธ์กัน
- ใช้การเปลี่ยนรูปเฉพาะการเปลี่ยนสถานะที่มีความหมาย เช่น ชุดคำสั่งเลือกหลายรายการ
- จุดเริ่มต้นสำหรับ transition แบบทำเอง: ประมาณ 150–250 มิลลิวินาที แล้วทดสอบด้วยสายตา
- เมื่อเปิด Reduce Motion ใช้การเปลี่ยนสถานะที่เรียบง่าย และไม่บังคับ morph / scale
- ไม่ทำ animation ซ้ำทุกสามวินาทีจากการ refresh สถานะไดรฟ์

## 7. แนวทางทางเทคนิค

### เงื่อนไขก่อนเริ่ม

โค้ดปัจจุบันเข้าถึง glass ผ่าน runtime เพื่อ build ด้วย SDK เก่าได้ การใช้ SwiftUI API ใหม่โดยตรงต้องมี SDK ที่รู้จัก API เหล่านั้นด้วย การใส่ `if #available(macOS 26, *)` อย่างเดียวไม่ทำให้ SDK เก่าคอมไพล์ API ใหม่ได้

- ตรวจ Xcode, Swift และ macOS SDK ที่ติดตั้งจริงทั้งเครื่องพัฒนาและ runner ของ GitHub
- ตั้งเป้า build ด้วย Xcode 26 / macOS SDK 26 หรือใหม่กว่าที่ทดสอบแล้ว
- คง deployment target macOS 13 พร้อม availability branch สำหรับ API รุ่นใหม่
- ยืนยัน build ได้ทั้ง Apple Silicon และ Intel ก่อนปรับ UI ในวงกว้าง

### โครงสร้างไฟล์ที่เสนอ

```text
native/
  Design/
    DesignTokens.swift          # ระยะ รูปทรง และค่าที่ใช้ร่วมกัน
    AppMaterials.swift          # วัสดุ macOS 26 และ fallback
    AppButtonStyles.swift       # ปุ่มและสถานะของระบบ
    SelectionAppearance.swift   # การเลือก hover และ keyboard focus
  Views/
    AppShell.swift              # split view / sidebar / toolbar
    OverviewView.swift
    ConnectedDrivesView.swift
    GroupsView.swift
    ServerDetailView.swift
    Sheets/
  NetworkDrives.swift           # จุดประกอบแอพและ state ที่ยังไม่แยก
  CredentialVault.swift         # คงพฤติกรรมการเก็บบัญชีเดิม
```

- แยกไฟล์ทีละส่วน พร้อมแก้รายการไฟล์ใน `scripts/build_app.py` ให้ตรงกัน
- แยก `GlassCard` ออกเป็นบทบาทของการ์ดข้อมูลและชุดควบคุม
- macOS 26: ทดลอง API แบบ typed เช่น `glassEffect`, glass button styles และ container
- macOS 13–15: ใช้วัสดุและปุ่มที่รองรับจริง ไม่มีการอ้าง API ใหม่จาก branch ที่ไม่ได้ป้องกัน
- ทบทวน `CardSelectionAnchor` หลังเปลี่ยนโครง List; จะถอดก็ต่อเมื่อ native selection ไม่มีกรอบเหลี่ยมกลับมา และ keyboard / VoiceOver ผ่านแล้ว
- ไม่เปลี่ยน protocol ของ Python service หรือรูปแบบข้อมูลผู้ใช้เพื่อปรับรูปลักษณ์

| 5 — ตรวจคุณภาพ | Accessibility, performance, ระบบเก่าและสอง CPU | รายการผลตรวจพร้อมข้อจำกัด |
| 6 — ส่งต่อ | Build, package และออกเวอร์ชันใหม่ | DMG / ZIP และปุ่มดาวน์โหลดที่ตรวจแล้ว |

ให้ทบทวนภาพและปฏิสัมพันธ์จากระยะ 1 ก่อนขยายไปทั้งแอพ หาก glass ทำให้ตัวอักษรอ่านยาก ให้ปรับวัสดุและลำดับชั้นก่อนเพิ่มความโปร่งใส

## 9. เกณฑ์รับงาน

### รูปลักษณ์

- [ ] Sidebar, toolbar และชุดคำสั่งรวมมีลำดับชั้นชัดเจน
- [ ] ไม่มีพื้นหลังเลือกเหลี่ยมหรือขอบซ้อนนอกการ์ด
- [ ] ชื่อไดรฟ์ ชื่อเครื่อง และสถานะอ่านได้ใน Dark / Light / System
- [ ] แถวข้อมูลไม่เป็นกระจกซ้อนกันหลายชั้น
- [ ] Resize แล้ว toolbar, sheet และรายการไม่ล้นหรือถูกบัง
- [ ] Empty / loading / error / offline states มีรูปทรงและภาษาสอดคล้องกัน

### การใช้งานและการช่วยการเข้าถึง

- [ ] Command-click, Shift-click, Command-A และเมนูคลิกขวาทำงานเดิม
- [ ] Keyboard focus มองเห็นได้ แม้ปรับ native selection highlight
- [ ] VoiceOver ระบุชื่อ สถานะ รายการที่เลือก และปุ่มได้ถูกต้อง
- [ ] Reduce Transparency / Increase Contrast / Reduce Motion ยังใช้งานได้ครบ
- [ ] ทดสอบหน้าต่าง active / inactive และพื้นหลังสว่าง / มืด
- [ ] Connect / Eject / group actions / Remember account ไม่มีพฤติกรรมถดถอย

### ประสิทธิภาพและการส่งมอบ

- [ ] Profile ก่อนและหลังด้วยรายการจำนวนใกล้เคียงการใช้งานจริง
- [ ] การเลื่อนและเลือกหลายรายการไม่สะดุดจากการเพิ่มเอฟเฟกต์
- [ ] การ refresh สถานะไม่สร้าง view identity ใหม่หรือรบกวน selection
- [ ] Build และ smoke test ผ่านทั้ง Apple Silicon / Intel
- [ ] ทดสอบ macOS 26 และ fallback บน macOS 13–15; หากยังไม่ได้ทดสอบบางรุ่นต้องระบุไว้
- [ ] ภาพที่ใช้ตรวจในเครื่องไม่ถูกอัปโหลดพร้อมชื่อเครื่อง IP หรือข้อมูลบัญชีจริง

## 10. ขอบเขต ณ วันที่ร่างแผน (ก่อนอนุมัติให้เริ่ม)

- ยังไม่แก้ source ของ UI หรือ build pipeline
- ยังไม่ยกระดับ macOS ขั้นต่ำหรือเปลี่ยนระบบเชื่อมต่อ
- ยังไม่เพิ่มเอฟเฟกต์เองเพื่อจำลองการหักเหของแสง
- ยังไม่เปลี่ยน app icon; พิจารณา Icon Composer แยกหลัง UI หลักลงตัว
- ยังไม่ออก Release สำหรับแผนนี้; v2.1.1 ที่แก้มุมโค้งเป็นงานก่อนหน้า
- การเพิ่มภาพก่อน/หลังต้องใช้ข้อมูลตัวอย่างที่ไม่ระบุตัวเครื่องจริง
