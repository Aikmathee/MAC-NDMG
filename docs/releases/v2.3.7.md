# MacNDMG 2.3.7

Connection-service requests now have bounded waits. If discovery, connection, eject diagnostics or a network operation stalls, MacNDMG reports a timeout and releases the UI instead of waiting indefinitely. A timeout does not prove that macOS cancelled an operation; live mount monitoring reconciles the actual result.

Service output uses a private temporary file to avoid waiting forever for subprocess pipe handles. Credentials remain on stdin, not in temporary files or command-line arguments. Only the service process started for that request is terminated; no user apps are stopped and no mounts are forced.

Stopping a group now includes its unattempted drives in the unresolved summary. Finder sign-in wording is shown only when a request is actually waiting in Finder.

Validation: 89 Python regression tests, including DHCP/NetBIOS changes, wrong accounts, disconnected-network results and duplicate-mount avoidance. Swift service tests cover success, incomplete output and a deadline while a descendant retains stdout. Both architectures run these checks in CI. These controlled tests do not replace broader testing on independent real networks.

Distribution remains ad-hoc signed. Developer ID signing and Apple notarization require a valid Apple Developer certificate and notarization credentials; no valid signing identity was available on the development Mac.
